# 轮腿步兵硬件基线、图16控制链待核实参数与当前假设

> 版本：2026-08-09 第三版  
> 目的：把目前已经掌握的硬件事实、原 `Final-Code` 的旧车配置、论文图16控制链需要的变量定义、为开发临时采用的假设，以及仍需实机/CAD核实的项目严格分开。当前控制范围只要求打通图16，不把离地检测、跳跃、自恢复等功能列为当前阻塞项。  
> 任何标记为 `ASSUMED`、`TO_VERIFY` 或 `CALIBRATED` 的参数，都不能因为写进代码而自动变成“已确认参数”。

---

## 1. 状态定义与使用规则

本文使用以下状态：

- **CONFIRMED**：现有仓库、用户已经提供的资料或厂家手册明确支持。
- **LEGACY_CONFIG**：原四麦轮步兵工程中的真实配置，但不代表新轮腿底盘仍应继续使用。
- **SOURCE_RECORDED**：用户提供的商品图/二手资料中明确写出，但资料权威性或版本存在疑问，需要与实物核对。
- **DERIVED**：由已确认或来源记录参数计算得到。
- **ASSUMED**：为了先写代码而人为指定，进入对应实机阶段前必须核实。
- **TO_VERIFY**：已知这个量必须存在，但目前没有可靠值。
- **CALIBRATED**：最终应通过实机标定得到，目前尚无最终值。
- **SOFTWARE_PLACEHOLDER**：仅用于主机/台架数据链、符号和限幅测试，禁止视为实机控制参数。

风险等级：

- **P0**：不核实就不允许给真实电机非零输出，或可能直接导致控制方向/通信错误。
- **P1**：不核实就不允许进行腿部闭环、VMC 或 LQR 平衡。
- **P2**：可先做低风险 bring-up，但高性能运动前必须核实。

来源优先级原则：

1. 实机铭牌、上位机读取、原理图、SolidWorks Mass Properties、实测数据；
2. 厂家官方手册/工程图；
3. 当前 `Final-Code` 中实际使用的配置；
4. 用户提供的商品参数图片；
5. 本文为了开发临时设定的占位值。

CAN 位时序为 Prescaler=3、BS1=10TQ、BS2=3TQ、SJW=1TQ；结合 APB1=42 MHz，CubeMX 计算结果为 1 Mbps。

当前 `Boards/bsp_can.c` 给 CAN1 和 CAN2 配置的是 **32-bit ID mask 全零过滤器**，也就是 bring-up 逻辑上基本接收所有 CAN ID；CAN1 使用 FilterBank 0，CAN2 从 FilterBank 14 开始，均进入 FIFO0。该配置属于 `LEGACY_CONFIG`。轮腿拓扑冻结后可根据需要收紧过滤器，但不能在 DM ID 尚未冻结时过早屏蔽反馈。

**对轮腿项目的影响：** CAN1/CAN2 的 1 Mbps 不再是假设；需要修改的是总线设备分配、错误恢复策略、发送失败处理和总线占用率，而不是先重新猜波特率。

## 9.3 IMU数据在当前代码中的单位陷阱

`Final-Code/User/Algorithm/MahonyAHRS_DSP.c` 当前 `Get_Angle1()` 把 `YAW/PITCH/ROLL` 转成 **degree**，而论文控制内部必须使用 rad。因此：

## 9.4 LQR参考向量的论文内部口径冲突

论文1.2.1一处写：

```text
x_ref = [0, 0, xd, 0.5*vd, 0, 0]^T
```


# 14. 参数替换和版本管理规则

所有参数必须集中到：

```text
FINAL-2026/User/WheelLeg/wheel_leg_config.h

```

例如：

```c
#define WL_WHEEL_RADIUS_M           0.075f      // ASSUMED A01
#define WL_WHEEL_GEAR_RATIO         15.7647059f // ASSUMED A02, conflict X01

#define WL_JOINT_TORQUE_BENCH_NM    5.0f        // ASSUMED A19
```

核实一个参数后必须同时：

1. 把状态更新为 `CONFIRMED` 或 `CALIBRATED`；
2. 写清来源：CAD 文件版本、实测日期、上位机截图/导出文件、厂家手册版本；
3. 若涉及五连杆，重新跑 FK/Jacobian 单元测试；
4. 若涉及质量/质心/惯量/轮半径/减速比，重新生成 A/B/K(L0)；
5. 单独 Git commit，避免把参数变更和算法大改混在一个提交中。
